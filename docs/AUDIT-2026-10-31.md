## 4. Bugs comprovados e corrigidos nesta sessão (working tree, sem commit)

### 4.1 `apps/web/postcss.config.js` quebrava `next build`
- Sintoma: `Error: Your custom PostCSS configuration must export a 'plugins' key` + warning de campo `default` não suportado. Causa: arquivo usava `exports.default` (Next exige export padrão CommonJS) e import residual sem sentido de `node:stream/consumers`.
- Correção: `module.exports = { plugins: { tailwindcss: {}, autoprefixer: {} } }`.
- Validação: `pnpm --filter web build` → exit 0, 4 páginas geradas.

### 4.2 `scripts/fix-prisma-client.cjs` não sincronizava o cliente Prisma
- Sintoma: API morria com `@prisma/client did not initialize yet`. O script saía com "Diretório alvo no store .pnpm não encontrado" porque calculava o target a partir do realpath do link `@prisma/client` (que aponta para fora da pasta do entry do store), nunca para `<store>/<entry>/node_modules/.prisma/client`.
- Segundo defeito: copiava somente arquivos soltos, ignorando diretórios — o cliente Prisma 6.x gera `runtime/` (ex.: `runtime/library.js`) e engines `.so.node`, causando `Cannot find module './runtime/library.js'`.
- Correção: resolver target como `<store>/<entry>/node_modules/.prisma/client` validando versão via realpath; cópia recursiva.
- Validação: `[fix-prisma-client] Cliente sincronizado...` + API sobe e health retorna 200 com DB ok.

### 4.3 Riscos de segurança observados (não alterados — decisão pendente)
- `apps/api/src/main.ts`: CORS `origin: true` + `credentials: true` — reflete qualquer origem com cookies. Aceitável em dev, inaceitável em produção. Recomenda-se restringir por lista de origens via env quando houver auth.
- `docker-compose.yml` e `.env.example`: credenciais `plataforma/plataforma` — apenas para dev local; production deve usar secrets externos. Manter fora de código real.
- Schema: `Session.tokenHash` único e expiração presentes, mas **sem índice em `Session.expiresAt`/`userId`** e sem índices de FK relevantes além dos únicos — avaliar ao implementar auth.
- Nenhuma rate limiting/middleware de segurança (helmet) — adicionar junto com auth.
